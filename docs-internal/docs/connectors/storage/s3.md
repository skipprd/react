# S3 Storage

The S3 storage adapter persists all artifacts to an Amazon S3 bucket. This provides durable, shared storage suitable for production deployments and multi-machine environments.

## Configuration

```yaml
storage:
  mode: s3
  bucket: my-react-bucket
```

| Field | YAML path | CLI flag | Env var | Description |
|---|---|---|---|---|
| `mode` | `storage.mode` | `--storage-mode` | `REACT_STORAGE_MODE` | Set to `s3` |
| `bucket` | `storage.bucket` | `--bucket` | `SKIPPR_S3_BUCKET` | S3 bucket name (required) |

## Object layout

All objects follow the [Keyspace](../../concepts/keyspace.md) layout:

```
s3://my-react-bucket/
└── {tenant}/
    └── {workspace}/
        └── {project_id}/
            ├── threads/{thread_id}.json
            ├── state/{thread_id}/state.json
            ├── logs/{thread_id}.log
            ├── catalog/{dataset_id}.yaml
            ├── dbt/...
            └── lancedb/
```

## Authentication

Uses the standard AWS credential chain:

1. Environment variables (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`)
2. AWS credentials file (`~/.aws/credentials`)
3. Instance profile / IAM role (EC2, ECS, Lambda)
4. AWS SSO

```bash
export AWS_ACCESS_KEY_ID="..."
export AWS_SECRET_ACCESS_KEY="..."
export AWS_DEFAULT_REGION="us-east-1"
```

## AWS permissions

The IAM identity needs these permissions on the configured bucket:

| Permission | Purpose |
|---|---|
| `s3:GetObject` | Read artifacts |
| `s3:PutObject` | Write artifacts |
| `s3:DeleteObject` | Delete threads |
| `s3:ListBucket` | List objects by prefix |
| `s3:HeadObject` | ETag checks |

Minimal IAM policy:

```json
{
  "Effect": "Allow",
  "Action": [
    "s3:GetObject",
    "s3:PutObject",
    "s3:DeleteObject",
    "s3:ListBucket",
    "s3:HeadObject"
  ],
  "Resource": [
    "arn:aws:s3:::my-react-bucket",
    "arn:aws:s3:::my-react-bucket/*"
  ]
}
```

## Operations

The `S3StorageAdapter` implements the `StorageAdapter` trait:

| Operation | Behaviour |
|---|---|
| `get_json` | `GetObject` + JSON parse |
| `put_json` | `PutObject` with `application/json` content type |
| `get_bytes` | `GetObject` raw bytes |
| `put_bytes` | `PutObject` with specified content type |
| `delete_object` | `DeleteObject` |
| `head_etag` | `HeadObject` — returns ETag if present |
| `list_prefix` | `ListObjectsV2` with prefix filter |

## When to use

S3 storage is recommended for:

- Production deployments
- Multi-machine / multi-process environments
- Durable persistence (survives instance termination)
- Shared state between `serve` and `run` invocations
